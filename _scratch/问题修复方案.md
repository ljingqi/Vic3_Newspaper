## 问题1｜投票日板块让模型自行判断写作任务

**结论**：`journal_save.py:6936` 在投票资格已由程序判定的情况下，仍让模型解读「判定结果」自己决定写哪边：

```python
ballot.append("请按判定结果描写投票日场景：拥有则写他履行权利的过程；"
              "不拥有则写他被拦在门外的情景。")
```

**改法**：`_pool_voting_data` 中 `ok, reason = _pool_vote_verdict(...)`（6922 行）已给出布尔结果，直接按 `ok` 分支下发具体任务：

```python
if ok:
    ballot.append("投票资格已确认：写他前往投票站、核验资格、领取选票并完成投票的过程。")
else:
    ballot.append("投票资格已被拒绝：写他在投票日被拦在投票站外、无法参与选举的情景。")
```

（保留上方 `判定结果：{reason}。` 事实行；程序侧不再让模型做「拥有与否」的二选一推理。）

**同类排查**：全库仅此一处「请按判定结果」式写法（其余「判定」均为程序逻辑注释）。杂志侧 `magazine.py` 投票文 ballot 板块 req 已是「资料已明确其投票资格，严格按资料写……」的正面指令，无需改。

## 问题2｜企业自定义名「达能食品」未生效

**核查结论（分两半）**：

1. **杂志路径（`_pool_building_text` → `_ownership_sentence`）已修复**：

   ```python

       place = "的".join(x for x in (ow.get("state_zh"), ow.get("building_zh")) if x)
   ```

## 问题3｜极权政体文风只覆盖法西斯/法团，缺共产主义

   - 辅信号（问题11落地后）：该国唯一/执政党模板为 `communist_party` → communist，`fascist_party` → corporatist。

3. 泛用极权文风（`generic`）把「统合运动」改为中性表述（如「国家机关刊物」），供无法归类的一党制使用。
4. `resolve_newspaper_style` / `resolve_magazine_voice` / `magazine._voice` 三处调用点按 flavor 选文案。

## 问题8｜数字与汉字之间多余空格

**结论**：模型输出常见「第三街 7 号」「第 18 个年头」「约 25.8%」，需正则后处理。

**改法**：在 `journal.py` 加共享函数并在两处规范化入口调用：
```python
_NUM_SPACE_RE = [
    re.compile(r"(?<=[\u4e00-\u9fff])\s+(?=\d)"),   # 汉字 空格 数字
    re.compile(r"(?<=\d)\s+(?=[\u4e00-\u9fff])"),   # 数字 空格 汉字
]
def clean_number_spaces(text):
    for r in _NUM_SPACE_RE:
        text = r.sub("", text)
    return text
```
- 报纸：`journal.py:_normalize_section_text`（4047 行，在 `_insert_thousand_separators` 之前调用）；
- 杂志：`magazine.py:_normalize_section`（2032 行）＋ 导言（`generate_magazine` 内 `intro = …strip()` 之后）。
