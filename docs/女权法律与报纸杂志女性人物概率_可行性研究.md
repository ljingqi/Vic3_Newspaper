# 按女权法律调整报纸/杂志「女性人物概率」· 可行性研究

> 研究日期：2026-08-16　|　对象：`journal_save.py` / `journal.py` / `magazine.py`
> 数据源：游戏 1.13 存档 `laws.database`、`common/laws/02_rights_of_women.txt`、
> `common/cultures/00_cultures.txt`、简中本地化 `laws_l_simp_chinese.yml`

## 一、结论（先说结果）

**可行，改动集中在 Python 伴生程序内，不动游戏端 mod。** 三个关键事实决定了可行性：

1. **现行女权法律在存档中可读。** `query_laws()` 已能从 `laws.database` 取出该国全部
   现行法律；女权法律组（`lawgroup_rights_of_women`）在 1.13 只有 5 条：法定监护 / 女性耕作（黑山专属）/
   有产妇女 / 女性工作 / 妇女选举权。目前快照只保留「本年度变化的法律」
   （`snap["laws"] = enacted + repealed`），但只要像 `free_speech_law`、`dop_law` 一样
   在 `extract_full_snapshot` 里多留一个 `women_law` 字段即可，是 1 行的事。
2. **名字池本来就有性别维度。** 游戏文化文件里每个文化都分别定义
   `male_common_first_names` 与 `female_common_first_names`；现有 `build_culture_names()`
   却把它们合并成了一个 `first` 池。实测 317 个有姓名池的文化**全部**同时具备男女名池，
   拆分后按性别取名几乎零成本。
3. **存档对随机角色没有性别字段**（`_ruler_info` 注释原文：「存档无性别字段, 随机角色默认男性」，
   只有历史模板角色可判性别）。也就是说「谁该是女性」由模组自己决定——实现时按法律概率从
   男/女名池取名，性别信号由名字本身承担。**提示词不额外标注性别、不加「军人一律为男性」
   的话术**（按需求约定）：士兵文章的军人/军官通过强制男名池实现，其余一律靠名字表达。

### 需要澄清的现状

当前「女性概率」并不是 0：男名池共 14,217、女名池共 4,217，合并后均匀抽取，
**女性名占比约 22.9%**，且随文化差异很大（实测最低 senufo 约 4.3%，最高 haratin 约 47.1%）。
也就是说现在报纸/杂志里已经会出现女性名字，只是：

- 概率不受法律控制，纯由各文化男女名池大小决定；
- 名字性别没有显式传给 LLM（提示词里只有「姓名已给定，全文必须原样使用」）。

> 本次实施约定：提示词**不**加「此人为男/女」提醒，也**不**加「军人、军官一律为男性」
> 的强调；性别只体现在名字来源于哪个名池。

报纸没有随机士兵人名：战事板块只用存档里的真实将领，不经过 `culture_person_name`，
所以「士兵文章除外」主要落在杂志的「战地与后方」文章。

### 2.2 法律数据现状

- `snap["laws"]` 只含本年度新施行 + 废除的法律（`extract_full_snapshot` 注释原文：
  「只保留本年度内发生变化的法律」），**不是**现行法律全集。
- `active_laws = query_laws(melted, cid)` 已计算出全集，但只抽了
  `free_speech_law` / `dop_law` / `govt_law` 三个字段存进快照，女权法律没有存。
- 女权法律组 5 条（`02_rights_of_women.txt`）：

| 法律 key | 中文名 | progressiveness | 备注 |
| --- | --- | --- | --- |
| `law_no_womens_rights` | 法定监护 | -100 | 起步法 |
| `law_women_in_the_fields` | 女性耕作 | -100 | `is_visible` 仅 `c:MON`（黑山专属） |
| `law_women_own_property` | 有产妇女 | -50 | |
| `law_women_in_the_workplace` | 女性工作 | 0 | 需科技 feminism |
| `law_womens_suffrage` | 妇女选举权 | +50 | 需科技 feminism + 选举权类法律 |

常规国家正常路径是 法定监护 → 有产妇女 → 女性工作 → 妇女选举权。

### 2.3 「士兵文章」的边界

只有杂志 `war_family`（战地与后方）是士兵文章：战地报道、士兵与营、后方家书、战火余烬。
其中「军官」不生成姓名（兵源样本只给职业/文化/宗教/生活水平），受提示词铁律
「未给出姓名的直接描写对象一律用身份/职业代称」约束；
所以「军官只能为男性」无需提示词话术：军官不命名，已命名的军人角色（士兵（主角））
直接强制从男名池取名。

## 三、实施方案

### 3.1 法律 → 女性概率映射（建议档位，可在 config 覆盖）

| 法律 | 建议女性概率 | 语义 |
| --- | --- | --- |
| 法定监护 | 5% | 女性几乎不出现在公共生活 |
| 女性耕作（黑山） | 5% | 女性只在田间劳作，报道可见度低 |
| 有产妇女 | 15% | 部分女性进入财产与民事场景 |
| 女性工作 | 30% | 女性进入职场，社会版面常见 |
| 妇女选举权 | 45% | 接近对半，公共生活性别均衡 |

数值仅为「显眼程度」标定，建议做成 `config.json` 覆盖表 `female_pct_by_women_law` 便于调参。

### 3.2 数据层（`journal_save.py`）

1. `build_culture_names()`：在保留 `first`（兼容旧调用）的同时增加 `male` / `female` 两个池
   （原始数据本就分开，解析几乎不变）。
2. `_crime_make_name(culture_key, rnd, gender=None)`：`gender` 给出时从对应池取，否则维持现行为。
3. `culture_person_name(culture_key, seed=None, gender=None, female_pct=None)`：
   未给 `gender` 时按 `female_pct` 用同一个 rnd 先掷性别再取名；种子不变 → 同年同角色稳定。
4. `person_names` / `person_names_block`：支持按角色传 `gender` 或整体 `female_pct`；
   输出块改为 `- 受访人姓名：安娜·穆勒（女，姓名已给定……）`。
5. `extract_full_snapshot`：`snap["women_law"] = next((l for l in _WOMEN_LAW_ORDER if l in active_laws), "law_no_womens_rights")`。
6. `build_journal_data`：透传 `data["women_law"]`（报纸与杂志共享同一份 data，一处即通）。
7. `_pool_crime_data`：把 `female_pct` 传给 `_crime_role_names`，受害者/凶手/证人各自独立掷性别。

### 3.3 提示词层（`journal.py` / `magazine.py`）

1. `_newspaper_person_name` + 三处访谈：只按 `data["women_law"]` 取概率，
   姓名行保持原样（不标注性别）。
2. `_mag_person_names`：非士兵文章按 `data["women_law"]` 的 `female_pct` 掷性别；
   士兵文章**不应用**法律概率（军属/战区平民维持合并池现行为），军人/军官角色强制男名池。
   提示词不加「军人、军官一律为男性」的话术——性别只体现在名字来源上。
3. `court_household`（府中长子/次子/幼女）与 `price`（餐桌主妇）等角色名自带性别，
   直接映射对应池，不参与概率抽样。
4. `voting`（选民（主角））为投票专属例外：妇女选举权（`law_womens_suffrage`）
   未生效时，合格选民必然为男性，该角色强制男名池，不参与法律概率；
   生效后才按该档概率（默认 45%）抽样。
5. （可选增强）在「政令与朝局」或社会板块把 `women_law` 中文名写入提示词，
   让文章自然呼应（如「妇女选举权实行后……」）。

### 3.4 稳定性与兼容

- 种子规则不变（`year|country|article|role`）：同年再生一致；法律跨年变化自然带来下一年分布变化。
- 姓名唯一性约束（`person_names` 去重循环）继续保留，男女混池也有效。
- 防御：某文化女名池为空（当前 317 个文化均非空）或查不到译名时回退现有行为。
- 真实角色（统治者/大臣/将领）不经本模块，性别不可由本功能改变；模板女王已有 `is_female` 判定，保持现状。

## 四、边界与注意事项

1. **名字≠性别**：游戏数据里个别名可能同时出现在男女两池（部分文化男女名池有重叠词），
   中文译名（如「艾丽卡」）对模型也不一定是强性别信号。按需求约定提示词不标注性别，
   一致性由名字承担；个别名字被模型理解为另一性别属于可接受范围。
2. **概率是独立抽样**：同一年同一篇文章可能出现多个女性或一个都没有，属正常随机；
   若想要「至少一位女性」等效果，可在 `person_names` 层加约束（可选）。
3. **不碰游戏端 mod**：本方案全部在 Python 伴生程序内完成，存档解析、提示词生成都无需改 Paradox 脚本。
4. **黑山专属法** `law_women_in_the_fields` 仅 `c:MON` 可见，映射表保留它仅为完整性。
